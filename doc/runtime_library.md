# StrideRuntime Static Library

`StrideRuntime` is a standalone, lightweight static library that provides the C-ABI runtime support functions called by compiled Stride programs (specifically string manipulation, formatting, parsing, and console I/O defined in `Strings.stride`).

Unlike `StrideJit`, `StrideRuntime` has **zero LLVM or parser dependencies**—it depends only on the standard C/C++ runtime library, making it suitable for linking with Ahead-of-Time (AOT) object files emitted by `StrideEnvironment::emitObjectFile`.

---

## 1. Architecture & Execution Modes

Stride `platformModule`s generate code in one of two ways:
1. **Inline LLVM IR (`llvm::` prefix)**: Arithmetic, comparisons, and bitwise operators (e.g., `Add`, `Multiply`, `Greater`) emit native LLVM instructions directly into the compiled function body and require no external library.
2. **External Runtime Calls (`@` prefix)**: Higher-level operations in `Strings.stride` (e.g., `@__stride_jit_string_format`, `@__stride_jit_string_concat_n`) emit external function calls (`declare ... @__stride_jit_string_*`) resolved at link time from `StrideRuntime`.

### Mode A: In-Memory JIT (`StrideEnvironment::compileInMemory`)
`StrideJit` links `StrideRuntime` publicly (`target_link_libraries(StrideJit PUBLIC StrideRuntime ...)`), and `StrideEnvironment::compileInMemory()` automatically registers all `__stride_jit_string_*` and `__stride_string_*` symbols in the ORC `JITDylib`. No additional setup is required.

### Mode B: Ahead-of-Time (AOT) Object Emission (`emitObjectFile` / `emitCHeader`)
When compiling a `.stride` file to a native object file (`.o` / `.obj`) and C header (`.h`):
1. `StrideEnvironment::emitObjectFile("output.o")` writes the compiled machine code for the target architecture. Any string operations called by the Stride program appear as undefined external symbol references (`__stride_jit_string_*`) in `output.o`.
2. `StrideEnvironment::emitCHeader("output.h")` generates the public C header declaring `<Domain>_init`, `<Domain>_process`, and the `StrideStringView` struct.
3. The final executable links `output.o` together with the `StrideRuntime` static library (`libStrideRuntime.a` on Linux/macOS or `StrideRuntime.lib` on Windows).

## 2. Linking & Dead-Code Stripping

`StrideRuntime` is built with **function-level section splitting** enabled so that linking against it only pulls in the specific runtime functions actually used by your Stride program:

| Compiler / Platform | Compile Flags on `StrideRuntime` | Linker Flag to Strip Unused Symbols |
| :--- | :--- | :--- |
| **MSVC (Windows)** | `/Gy` (Function-Level Linking / COMDATs) | `/OPT:REF` (enabled by default in Release builds) |
| **GCC (Linux / Embedded ARM)** | `-ffunction-sections -fdata-sections` | `-Wl,--gc-sections` |
| **Clang (macOS)** | `-ffunction-sections -fdata-sections` | `-Wl,-dead_strip` |

### CMake Usage Example

```cmake
add_executable(my_audio_app
  main.cpp
  ${CMAKE_CURRENT_BINARY_DIR}/stride_generated.o
)

target_link_libraries(my_audio_app PRIVATE StrideRuntime)
```

### Calling AOT-Compiled Code from C / C++

```cpp
#include "stride_generated.h" // Generated by StrideEnvironment::emitCHeader

int main() {
  StrideStringView inStr = {"Hello World", 11};
  StrideStringView outStr = {nullptr, 0};

  RootDomain_process(&inStr, &outStr);
  // outStr.data and outStr.length now hold the result
  return 0;
}
```

## 3. Core Data Types & ABI Conventions

Header: `include/stride/stridejit/strideruntime_string.h`

### `StrideStringView`
Mirrors the LLVM `_StringType` (`{ ptr, i32 }`) with standard layout and zero hidden fields:

```cpp
struct StrideStringView {
  const char *data{nullptr}; // Pointer to UTF-8 / ASCII byte buffer (not required to be null-terminated)
  int32_t length{0};         // Length in bytes
};
```
- **Size & Layout**: 16 bytes on 64-bit targets (`8`-byte pointer + `4`-byte `int32_t` + `4` bytes tail padding); 8 bytes on 32-bit targets (`4`-byte pointer + `4`-byte `int32_t`).

### `StrideFormatArg` & `StrideFormatArgType`
Used by heterogeneous `variadic` platform modules (such as `Format`) to pass a stack-allocated array of typed arguments across the C ABI without `va_list` platform differences:

```cpp
enum StrideFormatArgType : int32_t {
  STRIDE_FMT_ARG_INT    = 0, // Value stored in intVal
  STRIDE_FMT_ARG_REAL   = 1, // Value stored in realVal
  STRIDE_FMT_ARG_SWITCH = 2, // Value stored in intVal (0 or 1)
  STRIDE_FMT_ARG_STRING = 3, // Value stored in strVal
};

struct StrideFormatArg {
  int32_t typeTag{0};         // Offset 0
  int32_t intVal{0};          // Offset 4
  double realVal{0.0};        // Offset 8
  StrideStringView strVal{};  // Offset 16 (Total size: 32 bytes on 64-bit)
};
```

### Memory Model
- **Zero-Copy Slicing**: Substring, trimming, and tokenization (`Substring`, `Trim`, `TrimLeft`, `TrimRight`, `TokenAt`, `Tokenize`) never allocate memory; they return a `StrideStringView` pointing directly into the source string buffer with adjusted `data` and `length`.
- **Thread-Local Scratch Ring Arena**: Generative operations (`Concat`, `Repeat`, `Format`) allocate from a 64 KB thread-local ring buffer (`ScratchArena` in `src/strideruntime_string.cpp`), providing $O(1)$ bump allocation with zero heap fragmentation and automatic wrap-around.

## 4. Function Reference

`StrideRuntime` exposes two sets of `extern "C"` functions:
1. **`__stride_jit_string_*` (JIT / AOT Codegen ABI)**: Pointer-based ABI used by compiled Stride code. Struct inputs are passed by `const StrideStringView*` and struct outputs are written through a trailing `StrideStringView* out` parameter (`stride.struct_out`), avoiding platform-specific struct-by-value calling convention discrepancies.
2. **`__stride_string_*` (Host C++ Convenience API)**: By-value helpers using `StrideStringView` and `int64_t`.

### 4.1 Codegen Entry Points (`__stride_jit_string_*`)

#### Slicing & Trimming (Zero-Copy)
| Function Signature | Stride Module | Description |
| :--- | :--- | :--- |
| `void __stride_jit_string_substring(const StrideStringView *src, int32_t start, int32_t len, StrideStringView *out)` | `Substring` | Extracts a slice of `src` starting at `start` of length `len` (`len < 0` slices to end of string). Clamps out-of-bounds indices safely. |
| `void __stride_jit_string_trim(const StrideStringView *src, const StrideStringView *chars, StrideStringView *out)` | `Trim` | Strips any leading and trailing characters present in `chars` from `src`. |
| `void __stride_jit_string_trim_left(const StrideStringView *src, const StrideStringView *chars, StrideStringView *out)` | `TrimLeft` | Strips leading characters present in `chars` from `src`. |
| `void __stride_jit_string_trim_right(const StrideStringView *src, const StrideStringView *chars, StrideStringView *out)` | `TrimRight` | Strips trailing characters present in `chars` from `src`. |

#### Search, Comparison & Inspection

| `int32_t __stride_jit_string_find_last(const StrideStringView *haystack, const StrideStringView *needle)` | `FindLast` | Returns the 0-based byte index of the last occurrence of `needle`, or `-1` if not found. |
| `bool __stride_jit_string_contains(const StrideStringView *haystack, const StrideStringView *needle)` | `Contains` | Returns `true` if `needle` occurs anywhere within `haystack`. |

| :--- | :--- | :--- |
| `int32_t __stride_jit_string_parse_int(const StrideStringView *str, int32_t defaultVal)` | `Parse@String_Int` | Parses a base-10 integer using `std::from_chars` (ignoring leading/trailing whitespace). Returns `defaultVal` on invalid input. |
| `double __stride_jit_string_parse_real(const StrideStringView *str, double defaultVal)` | `Parse@String_Real` | Parses a floating-point number using `std::from_chars`. Returns `defaultVal` on invalid input. |

#### Tokenization (Zero-Copy)

| :--- | :--- | :--- |

| :--- | :--- | :--- |

| `void __stride_jit_string_print(const StrideStringView *str)` | `Print` | Writes `str` to `stdout` without a trailing newline and flushes. |
| `void __stride_jit_string_println(const StrideStringView *str)` | `PrintLn` | Writes `str` followed by `\n` to `stdout` and flushes. |
